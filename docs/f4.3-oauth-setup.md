# F4.3 — OAuth Setup: Prerequisitos manuales

**Dacmos Password Manager — Feature F4.3**  
**Autor:** DacmosGroup  
**Estado:** Pendiente de completar antes de la primera verificación end-to-end

> Este documento es una guía operativa, no técnica. Los pasos deben
> completarse **antes de ejecutar los criterios de verificación V1–V5**
> del roadmap. Sin estos pasos, los flujos OAuth fallarán con errores
> de "client_id inválido" o "redirect_uri no autorizado".

---

## Sección A — Google Cloud Console (OAuth para Google Drive)

> **Por qué:** La extensión Chrome usa un Client ID de tipo "Extensión de Chrome"
> que no funciona en una PWA. La PWA necesita un Client ID de tipo "Aplicación web"
> con los orígenes autorizados correctos.

### Pasos

- [ ] **1.** Ir a [console.cloud.google.com](https://console.cloud.google.com) → seleccionar el proyecto de Dacmos PM.

- [ ] **2.** Menú izquierdo → **APIs y servicios** → **Credenciales**.

- [ ] **3.** Hacer clic en **+ Crear credencial** → **ID de cliente de OAuth 2.0**.

- [ ] **4.** Tipo de aplicación: seleccionar **Aplicación web**.

- [ ] **5.** Nombre: `Dacmos PM — PWA` (o cualquier nombre descriptivo).

- [ ] **6.** En **Orígenes de JavaScript autorizados**, añadir:
  - `https://dacmos-pm-pwa.pages.dev`
  - `https://dpm.dacmosgroup.co`
  - `http://localhost:8080` (opcional, para pruebas locales)

> ⚠️ **Acción manual requerida:** Si el dominio de producción cambia en el futuro,
> estas URIs deben actualizarse también en Google Cloud Console y Azure Portal.
> El código por sí solo no es suficiente — los portales de OAuth validan
> que la URI de redirect coincida exactamente.

- [ ] **7.** En **URIs de redireccionamiento autorizados**: **dejar vacío**.
  > GIS Token Client no usa redirect URIs — el token se retorna
  > directamente al callback JavaScript.

- [ ] **8.** Hacer clic en **Crear**.

- [ ] **9.** Copiar el **ID de cliente** resultante (formato: `XXXXXXXXXX-xxxx.apps.googleusercontent.com`).

### Variable a reemplazar en el código

Abrir [web/src/auth/google-auth.js](../web/src/auth/google-auth.js) y reemplazar:

```javascript
const CLIENT_ID = 'TU_GOOGLE_CLIENT_ID'
```

por:

```javascript
const CLIENT_ID = 'PEGAR_AQUÍ_EL_CLIENT_ID_COPIADO_EN_PASO_9'
```

- [ ] **10.** Reemplazar el placeholder en `google-auth.js` y verificar que el archivo fue guardado.

### Verificación rápida (sin la PWA)

- [ ] **11.** Confirmar en la consola de Google Cloud que la API de Google Drive v3 está habilitada en el proyecto:  
  **APIs y servicios** → **Biblioteca** → buscar "Google Drive API" → debe aparecer como **Habilitada**.

## Sección B — Azure Portal (OAuth para OneDrive)

> **Por qué:** El App Registration existente fue configurado con redirect URIs
> de tipo "Aplicación móvil y de escritorio" para la extensión Chrome
> (`https://<ext-id>.chromiumapp.org/`). La PWA necesita URIs de tipo
> "Single Page Application" registradas explícitamente.

### Pasos

- [ ] **1.** Ir a [portal.azure.com](https://portal.azure.com) → **Microsoft Entra ID** (antes Azure AD).

- [ ] **2.** Menú izquierdo → **Registros de aplicaciones** → buscar el App Registration de Dacmos PM.
  > El Client ID del registro existente es: `e344398b-b03a-4819-8679-f12ff50e7c4d`

- [ ] **3.** En la página del registro → menú izquierdo → **Autenticación**.

- [ ] **4.** En la sección **Single-page application**, hacer clic en **Agregar una URI**.

- [ ] **5.** Añadir las siguientes URIs de redirección (una por una):
  - `https://dacmos-pm-pwa.pages.dev/blank.html`
  - `https://dpm.dacmosgroup.co/blank.html`
  - `http://localhost:8080/blank.html` (opcional, para pruebas locales)

> ⚠️ **Acción manual requerida:** Si el dominio de producción cambia en el futuro,
> actualizar también estas URIs en Azure Portal → Autenticación → Single-page application.

- [ ] **6.** Hacer clic en **Guardar**.

- [ ] **7.** Verificar que las URIs nuevas aparecen bajo **Single-page application** (no bajo "Aplicación móvil y de escritorio").

### Variable en el código

El Client ID de Microsoft ya está presente en el código:

- [web/src/auth/microsoft-auth.js](../web/src/auth/microsoft-auth.js) → `const CLIENT_ID = 'e344398b-b03a-4819-8679-f12ff50e7c4d'`
- [web/blank.html](../web/blank.html) → `clientId: 'e344398b-b03a-4819-8679-f12ff50e7c4d'`

**No se requiere ningún cambio de código en este caso.**

- [ ] **8.** Confirmar que el scope `Files.ReadWrite.AppFolder` está en los permisos de API del registro:  
  **Permisos de API** → debe aparecer `Microsoft Graph` → `Files.ReadWrite.AppFolder` con estado "Concedido".
